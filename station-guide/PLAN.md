# 군자역 실내 길안내 프로토타입 구현 계획

근거: 「2026 서울관광 프롬프톤 개발계획서」, data.zip(군자역 영상 + 서울교통공사 공공데이터)

## 진행 방침 (2026-11-27 변경)
- **개인 테스트 위주**. 공개 배포·현장 촬영은 하지 않는다.
- **추가 자료 없음**. 지금 가진 것(계획서, data.zip의 영상 2개·CSV, 편의시설 API 키, 공개 구내도·시간표)만으로 목표를 최대한 채운다.
- 그래서 바꾼 것:
  - 실제 휴대폰 사진 재측정 → **합성 표지판 정확도 측정**(브라우저, 앱과 같은 OCR)으로 대체
  - 실시간 열차 도착정보(키 없음) → **공개 열차시간표 기준 "다음 열차"**로 대체, 키가 생기면 실시간 우선
  - 공개 배포 → **같은 와이파이의 휴대폰에서 PC 개발 서버로 접속**(QR)
  - LLM 판별 → 코드는 두되 키가 없으면 꺼짐(비용 0)
  - 데모 영상 → **결과 문서 + 화면 캡처**(docs/RESULTS.md, docs/progress)

## 확정한 것
- 대상 역: **군자역(5·7호선 환승)**. 현장 영상이 있는 역.
- 형태: 로그인 없는 모바일 웹, 한국어/영어.
- 3D: 역 구조를 JSON(층, 구역, 노드, 간선)으로 적고 three.js로 생성. 실사 재구성은 하지 않는다.
- 비용: 운영 중 API 호출 최소화. 표지판 위치 추정 = 브라우저 OCR → 규칙 매칭 → 버튼 확인 → (키가 있으면) LLM 1회.

## 기술 구성
| 층 | 내용 |
|---|---|
| 프론트 | Vite + React + react-three-fiber(three.js), PWA |
| 역 데이터 | `app/src/data/gunja.json` (`app/scripts/build-gunja.mjs`로 생성) |

| 실시간 | `/api/facilities`(엘리베이터·에스컬레이터 가동, 5분 캐시), `/api/arrivals`(키 있을 때) |
| 시간표 | `app/src/data/timetable.json` (`npm run build:timetable`) |

## 시나리오
- A. 출발(출구/승강장/찾은 위치)·목적지(5·7호선 역/출구) → 단계 안내("도착했어요") → 탈 열차 앞. 승차권 옵션 시 발매기 경유 + 발권 안내. 마지막에 다음 열차.
- B. 길 잃음 → 표지판 사진 → 영역 지정 → OCR 매칭 → 후보/번호 버튼 확인 → 현재 위치에서 A로 이어짐.
