지하철 역사 길안내 — 방안 정리

외국인 관광객이 지하철 역사 안에서 길을 잃는 문제를 다룹니다. 지금까지 나온 방안, 빠진 이유, 최종 방식과 필요한 것을 정리했습니다.

웹 브라우저에서는 기압계 값을 읽을 수 없는 것으로 알고 있습니다(미확인). 그래서 웹 기준 최종안은 층 변화를 그래프로 처리합니다.

2. 최종 방식: 걸음 추적 + 갈림길 확인

  1. 1
    시작

    지상 출구 앞에서 GPS로 몇 번 출구인지 잡습니다. 시작 방향은 계단 방향으로 정합니다.

    역 안에서 앱을 켰다면 목록에서 위치를 고릅니다.

  2. 2
    이동 추적 (PDR, 보행자 추측항법)

    가속도계로 걸음을 세고 보폭을 곱해 거리를 구합니다. 방향은 자이로로 회전을 누적해 구합니다.

    가속도를 두 번 적분하는 방식은 오차가 커서 쓰지 않습니다. 나침반은 철골 때문에 틀어지기 쉬워 보조로만 씁니다.

  3. 3
    맵 매칭

    추정 위치를 그래프에서 가장 가까운 통로 위로 붙입니다.

    옆으로 벗어나는 오차가 사라지고, 통로를 따라 얼마나 왔는지에 대한 오차만 남습니다.

  4. 4
    층 변화

    계단이나 에스컬레이터 엣지를 지나면 그래프에서 층을 바꿉니다. 맞지 않으면 사용자가 층을 직접 고릅니다.

    네이티브 앱으로 만들 경우에는 기압계를 보조로 붙입니다.

  5. 5
    갈림길 확인

    3D 모델의 사용자 시점 화면을 보여주고 "이 모습인가요?"를 묻습니다.

    맞음 → 갈 방향을 화살표로 표시하고, 쌓인 위치 오차를 0으로 되돌림
    틀림 → 근처 후보 두세 곳 중에서 고르게 함

흔들리는 경우

  • 에스컬레이터와 무빙워크에서는 걷지 않으니 거리가 잡히지 않습니다. 해당 엣지를 통과한 것으로 처리합니다.
  • 폰을 주머니에 넣었다 꺼내면 방향 추정이 흐트러집니다. 다음 갈림길 확인에서 바로잡습니다.

3. 필요한 것

데이터 (시연할 역 하나)

  • 노드 그래프: 갈림길, 개찰구, 계단·에스컬레이터 양끝, 승강장, 출구를 노드로 둠. 노드에는 층과 좌표, 엣지에는 길이와 방향
  • 3D 모델: 그래프 좌표로 통로는 상자, 계단은 경사면으로 단순하게
  • 현장 작업: 역을 직접 걸으며 통로 길이(걸음 수)와 방향을 재고 갈림길 모습을 기록

구현

  • 센서: DeviceMotion·DeviceOrientation API. iOS는 버튼을 눌렀을 때 권한 요청 필요
  • 걸음 감지, 방향 누적, 맵 매칭: 직접 구현
  • 경로: 그래프 최단경로(다익스트라)
  • 화면: three.js 3D 뷰, 화살표 안내, 다국어 문구

4. 아직 확인하지 않은 것

  • iOS 사파리의 WebXR 지원 여부, 웹의 기압계 접근 가능 여부 → 웹으로 갈지 네이티브 앱으로 갈지가 여기서 갈림
  • 실제 역에서의 PDR 오차 → 폰으로 한 구간을 걸어 시험
  • 시연할 역 선정
  • 기획안의 확장안(1회용 승차권 구매 안내), INGUIDE AR과의 차별점 → 아직 다루지 않음
