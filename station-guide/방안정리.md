# 지하철 역사 길안내 — 방안 정리

외국인 관광객이 지하철 역사 안에서 길을 잃는 문제를 다룹니다. 아래는 지금까지 나온 방안, 빠진 이유, 최종 방식과 필요한 것을 정리한 내용입니다.

> 주의: 웹 브라우저에서는 기압계 값을 읽을 수 없는 것으로 알고 있습니다(미확인). 그래서 웹 기준 최종안은 층 변화를 그래프로 처리합니다.

---

## 1. 나왔다가 빠진 방안

| 방안 | 낸 사람 | 빠진 이유 | 남은 쓰임 |
|---|---|---|---|
| 실시간 AR (WebXR, 카메라 추적) | Claude | iOS 사파리가 WebXR을 지원하지 않음(미확인). 측위 문제가 풀리지 않음. 해커톤 기간에 만들기 무거움 | 시연 기기를 안드로이드로 정하면 다시 검토 가능 |
| 3D 모델에 경로만 그려 보여주기 | 사용자 | 지금 모델의 어디에 있는지 사용자가 직접 찾아야 해서 "지도를 봐도 모른다"는 문제가 남음 | 최종안의 안내 화면으로 들어감 |
| GPS로 역 안 위치 잡기 | 사용자 | 지하에서는 GPS가 잡히지 않음. 네트워크 위치는 오차가 수십 m 이상이라 통로 구분이 안 됨 | 어느 역인지 판별하고, 지상에서 시작점을 잡는 데만 씀 |
| 표지판 문구로 위치 잡기 | Claude | 같은 표지판이 반복돼 위치가 특정되지 않음. 표지판이 안 보여서 쓰는 앱이 표지판을 찾게 하는 건 모순 | 없음 |
| 현위치 안내도, 안전문 번호 | Claude | 현위치 안내도는 큰 역에만 있음(현장 경험). 안전문은 길을 잃는 곳이 아님 | 없음 |
| 사진 일치율 (기획안 3번) | 기획안 | 노드마다 기준 사진을 준비해야 함. 혼잡이나 광고 교체에 약함 | 채택하지 않음 |
| 경로를 nC2로 미리 계산 | 사용자 | 그래프가 작아 요청마다 최단경로를 바로 계산해도 됨 | 없음 |
| Blender MCP 연동 | 질문 | 필수 아님. 그래프 좌표로 three.js에서 단순 모델을 그리면 됨 | 외형을 다듬고 싶을 때만 Blender 사용 |

## 2. 최종 방식: 걸음 추적 + 갈림길 확인

1. **시작**: 지상 출구 앞에서 GPS로 몇 번 출구인지 잡습니다. 시작 방향은 계단 방향으로 정합니다. 역 안에서 앱을 켰다면 목록에서 위치를 고릅니다.
2. **이동 추적 (PDR, 보행자 추측항법)**
   - 가속도계: 걸을 때 생기는 위아래 흔들림으로 걸음을 세고, 걸음 수에 보폭을 곱해 거리를 구합니다. 가속도를 두 번 적분하는 방식은 오차가 커서 쓰지 않습니다.
   - 자이로: 회전한 양을 누적해 현재 방향을 구합니다. 나침반은 역 안에서 철골 때문에 틀어지기 쉬워 보조로만 씁니다.
3. **맵 매칭**: 추정 위치를 그래프에서 가장 가까운 통로 위로 붙입니다. 그러면 옆으로 벗어나는 오차가 사라지고, 통로를 따라 얼마나 왔는지에 대한 오차만 남습니다.
4. **층 변화**: 계단이나 에스컬레이터 엣지를 지나면 그래프에서 층을 바꿉니다. 맞지 않으면 사용자가 층을 직접 고릅니다. 네이티브 앱으로 만들 경우에는 기압계를 보조로 붙입니다.
5. **갈림길 확인**: 갈림길에서 3D 모델의 사용자 시점 화면을 보여주고 "이 모습인가요?"를 묻습니다.
   - 맞으면 갈 방향을 화살표로 표시하고, 쌓인 위치 오차가 여기서 0으로 돌아갑니다.
   - 틀리면 근처 후보 두세 곳 중에서 고르게 합니다.

**흔들리는 경우**
- 에스컬레이터나 무빙워크에서는 걷지 않고 이동하니 거리가 잡히지 않습니다. 해당 엣지를 통과한 것으로 처리합니다.
- 폰을 주머니에 넣었다 꺼내면 방향 추정이 흐트러집니다. 다음 갈림길 확인에서 바로잡습니다.

## 3. 필요한 것

### 데이터 (시연할 역 하나)
- **노드 그래프**: 갈림길, 개찰구, 계단·에스컬레이터 양끝, 승강장, 출구를 노드로 둡니다. 각 노드에는 층과 좌표를, 각 엣지에는 길이와 방향을 넣습니다.
- **3D 모델**: 그래프 좌표로 통로는 상자, 계단은 경사면으로 단순하게 만듭니다.
- **현장 작업**: 역을 직접 걸으며 통로 길이(걸음 수)와 방향을 재고, 갈림길 모습을 기록합니다.

### 구현
- **센서**: DeviceMotion·DeviceOrientation API. iOS는 버튼을 눌렀을 때 권한 요청을 띄워야 합니다.
- **걸음 감지, 방향 누적, 맵 매칭**: 직접 구현합니다.
- **경로**: 그래프 최단경로 계산(다익스트라).
- **화면**: three.js 3D 뷰, 화살표 안내, 다국어 문구.

## 4. 아직 확인하지 않은 것

- iOS 사파리의 WebXR 지원 여부, 웹의 기압계 접근 가능 여부 → 웹으로 갈지 네이티브 앱으로 갈지가 여기서 갈림
- 실제 역에서의 PDR 오차 → 폰으로 한 구간을 걸어 시험
- 시연할 역 선정
- 기획안의 확장안(1회용 승차권 구매 안내), INGUIDE AR과의 차별점 → 아직 다루지 않음
