# 새 역 실내 길안내 데이터 만들기 — 도봉산역 검증용 프롬프트

> 이 문서 전체를 새 세션에 붙여 넣는다. 군자역을 만들면서 고친 문제들을 규칙과 자동 검사로 옮긴 것이다.
> 도봉산역을 만들며 새로 나온 문제도 규칙으로 넣었다("도봉산역에서 추가" 표시, 근거는 `docs/RESULTS-dobongsan.md` 4절).
> 도봉산역 데이터는 이미 있으므로, 다음 역에 쓸 때는 0절의 역 이름·파일 이름만 바꾼다.
> 목적: 새 역(도봉산역)을 **처음부터 한 번에** 이 문제들 없이 만들 수 있는지 확인.

---

## 0. 작업 지시

`app/`의 군자역 실내 길안내 앱(Vite + React + react-three-fiber)에 **도봉산역** 데이터를 추가하라.

- 엔진(경로·안내 단계·3D·표지판 인식)은 그대로 쓴다. 역 데이터와 그 생성 스크립트, 역별 테스트만 새로 만든다.
- **군자역 파일은 수정하지 않는다**: `app/scripts/build-gunja.mjs`, `app/src/data/gunja.json`, 군자역 테스트.
- 새 파일:
  - `app/scripts/build-dobongsan.mjs` → `app/src/data/dobongsan.json`
  - 역 전환: URL 쿼리 `?station=dobongsan`. 기본은 군자역.
- 단계마다 실제 화면 캡처를 `docs/progress/dobongsan-*.jpg`로 저장하고 사용자에게 보여 준다.
- API 키는 프로젝트 루트 `.env.local`의 `STATION_API_KEY`. **값을 출력하거나 다른 곳에 쓰지 않는다.**

## 1. 자료 (이것만 쓴다)

| 자료 | 얻는 법 | 쓰는 곳 |
|---|---|---|
| 역 이용 및 비상대피 안내도 | `http://www.seoulmetro.co.kr/common/resources/cyber/fileView.jsp?fileName=in_{역코드}.jpg`. 호선마다 1장, 역코드는 서울교통공사 stnCd | 구역·계단·출구 배치(3D 그림), 층·연결 위치(단면도) |
| 편의시설위치정보 API | `https://apis.data.go.kr/B553766/facility/getFcElvtr`, `getFcEsctr` (stnNm으로 조회) | 엘리베이터·에스컬레이터 목록, 층, 위치 설명(dtlPstn), 실시간 가동 |
| 역사심도·건축·면적정보 CSV | 공공데이터포털 | 층 깊이, 승강장 길이·형식(섬식/상대식) |
| 환승정보 CSV | 공공데이터포털(국가철도공단_서울교통공사_환승정보) | 환승 빠른 칸·문 → 환승 계단 위치 검증 |
| 사이버스테이션 열차시간표 | `app/scripts/build-timetable.mjs` 참고 | 다음 열차 |

**먼저 확인할 것**
- 도봉산역은 1호선과 7호선이 만난다. 1호선 구간은 운영사가 서울교통공사가 아닐 수 있다. 운영사를 확인한다.
- 위 자료 중 1호선 쪽에 없는 것은 "없음"으로 표시하고 근사로 채운다. 근사로 채웠다는 사실을 데이터 주석과 결과 문서에 남긴다.
- 역코드와 API 역명은 추측하지 말고 조회로 확인한다.
- **운영사가 다른 노선은 칸 수와 통행 방향을 따로 적는다.** 예: 코레일 1호선은 10칸, 왼쪽 통행(서울교통공사 노선은 오른쪽 통행). 시간표·API가 없는 노선은 화면에 "자료 없음"을 띄운다. (도봉산역에서 추가)
- **지상·고가역이면 지하역 가정(지상 → 지하 대합실 → 승강장)을 쓰지 않는다.** 층 이름과 층 버튼을 역에 맞게 새로 정하고, 출구가 여러 높이에 있을 수 있음을 확인한다(도봉산 1-1번 출구는 지상2층 높이). (도봉산역에서 추가)

## 2. 배치 규칙 (군자역에서 틀렸던 것들)

### 2-1. 자료 읽기
1. **안내도는 3D 그림과 단면도를 둘 다 본다.**
   - 3D 그림에서는 구역 모양과 개찰구 안팎을 읽는다.
   - 단면도에서는 층 사이 연결이 어디에 있고 어느 방향으로 내려가는지 읽는다.
   - 그림은 원본 해상도로 확대해서 읽는다.
2. **단면도 축척:** 승강장 길이(건축정보)를 그림의 승강장 폭에 맞춰 m/px를 구한다. 출구·계단·엘리베이터 위치를 이 축척으로 환산한다. 오차(±5m)는 결과에 적는다.
   - **자료끼리 어긋나면 숫자로 된 자료를 먼저 따른다:** 환승정보(빠른 칸·문), API dtlPstn(칸-문) → 3D 그림 → 단면도 가로 위치 순. 단면도는 층 연결과 내려가는 방향만 믿고, 가로 위치는 참고만 한다. 어긋난 거리는 결과에 적는다. (도봉산역: 단면도 계단이 환승 빠른 문과 20~30m 어긋났다)
3. **API 문자열:** 저장해 둔 스냅샷은 한글이 깨졌을 수 있다. 위치 설명(dtlPstn 등)은 API를 UTF-8로 다시 받아 원문으로 확인한다.

### 2-2. 구역과 개찰구
4. **개찰구 밖과 안을 먼저 정한다.**
   - 출구 계단이 모이는 곳이 보통 개찰구 밖이다. 개찰구는 개찰구 안 구역이 개찰구 밖 구역과 만나는 경계에 둔다.
   - 군자역은 처음에 이걸 반대로 만들었다.
5. **개찰구 안팎 경계에는 개찰구 말고 다른 통로를 만들지 않는다.** 자동 연결점(포털)도 만들지 않는다.
6. **엘리베이터가 개찰구 밖에 있으면** 그 앞에 개찰구를 둔다. 아니면 요금을 안 내고 승강장에 들어가는 길이 생긴다. 이 개찰구 위치가 추정이면 그렇다고 적는다.
6-1. **개찰구 밖 구역이 둘 이상이면 서로 어떻게 이어지는지 먼저 정한다.** (도봉산역에서 추가)
   - 역 안(개찰구 밖)으로 이어지면 그 통로를 넣는다.
   - 이어지지 않으면 출구끼리 경로가 개찰구를 두 번 지나 요금을 내게 된다. 이런 경로는 안내하지 않고 "역 밖 길로 가세요"를 띄운다(엔진 `crossesPaidArea`). 몇 쌍이 해당하는지 결과에 적는다.

### 2-3. 계단·에스컬레이터·엘리베이터
7. **자료에 있는 것만 넣는다.**
   - 에스컬레이터는 API 목록에 있는 것만 넣는다.
   - 계단은 단면도나 3D 그림에 보이는 것만 넣는다.
   - 군자역에서는 근거 없이 넣은 승강장 에스컬레이터와 가운데 계단을 나중에 뺐다.
8. **계단·에스컬레이터는 위·아래 입구 노드를 따로 둔다.**
   - 수평 길이 = 층 높이 차 × 경사. 계단 1.7, 에스컬레이터 1.75.
   - 내려가는 방향은 단면도를 따른다.
9. **승강장 위 구조물 위치**
   - 섬식이면 승강장 폭 가운데에, 상대식이면 승강장 폭 안에 놓는다.
   - 양쪽 안전문 앞에 1m 이상 통로를 남긴다. 선로로 튀어나오면 안 된다.
10. **엘리베이터 위치**
    - API 위치 설명의 칸-문 번호(예: "장한평 방면 5-3")를 문 위치 모델로 계산해서 맞춘다. 8m 안이면 맞다.
    - 군자역은 1·2호기가 서로 바뀌어 있었다.
11. **출구 엘리베이터는 출구 계단·에스컬레이터를 가로막지 않는 쪽에 둔다.**

### 2-4. 걷는 길
12. **개찰구를 지나면 바로 앞 계단 입구로 곧장 잇는다.** 가운데 지점을 거쳐 돌아가지 않게 한다.
13. **트인 공간(대합실·통로·승강장)은 같은 직사각형 구역 안 두 지점을 곧장 잇는다.**
    - 계단 구멍·구조물·엘리베이터를 가로지르는 선은 만들지 않는다.
    - 구조물 네 모서리 바로 바깥에 비켜 가는 지점을 자동으로 둔다. 화면에는 그리지 않는다.
    - 손으로 그은 연결선도 구조물을 가로지르면 빌드할 때 뺀다.
14. **맞닿은 두 트인 구역 사이 연결점**
    - 맞닿은 변이 20m를 넘으면 가운데와 양 끝(1.5m 안쪽)에 둔다.
    - 개찰구 경계(규칙 5)에는 두지 않는다.
15. **타는 곳 노드는 승강장 계단을 내려온 쪽에 둔다.** "뒤로 돌아서 가세요"가 나오지 않게 한다.
    - 승강장에 들어오는 곳(계단·엘리베이터·환승 통로)이 여러 곳이면, **모든 곳에서 앞으로 걸어 닿는 자리**(들어오는 곳들 사이)에 둔다. 한쪽에만 맞추면 다른 쪽에서 오는 사람이 한 단계에 145m를 걸었다. (도봉산역에서 추가)
15-1. **긴 승강장(150m 이상)·긴 통로에는 가운데 확인 지점(이름 있는 junction)을 둔다.** 트인 공간에서 곧장 잇는 연결은 100m 이하로 제한한다. 아니면 끝에서 끝까지 한 단계가 150m를 넘는다. (도봉산역에서 추가)

### 2-5. 환승 검증
16. 환승정보 CSV의 빠른 칸·문이 환승 계단 바로 앞에 오는지 확인한다.
    - 군자역에서 5→7은 1-1·8-4 = 승강장 양 끝 계단, 7→5는 5-1·5-2 = 승강장 가운데 계단이었다.
    - 안 맞으면 계단 위치를 다시 본다.

## 3. 화면 규칙 (엔진에 이미 있음 — 새 역에서도 동작하는지 확인)

- 한 안내 단계 = 한 층.
  - 층을 넘기 전 계단·엘리베이터 입구에서 단계를 끊는다.
  - 화면에는 그 단계가 끝나는 층만 보인다. 지상과 B1은 한 판으로 묶는다.
- 위층 바닥에는 계단 자리에 구멍과 난간이 있다. 가장 아래 보이는 층 바닥은 진하게 그린다.
- 개찰구(기계 줄), 발매기, 개찰구 안 울타리, 화장실·안내 표지, 층 이름표가 보인다.
  - 엘리베이터에는 서는 층과 멈춤 여부가 표시된다.
- 승강장에는 칸-문 번호, 환승 빠른 문(초록), "여기서 타요" 문이 보인다.
  - 열차는 한 번 들어와 서 있다가 시간표 출발 시각에 떠난다.
- 안내 문장에는 다음 정보가 붙는다.
  - 계단·개찰구를 지난 뒤 방향(왼쪽/오른쪽)
  - 확인용 주변 표식
  - 엘리베이터 버튼 층
- '내 앞' 시점은 지금 서 있는 방향 뒤에서 본다. 100°가 넘게 꺾이는 곳에서는 돌아선 뒤의 방향으로 본다.
- 끌기로 이동, 오른쪽 끌기로 회전, 휠로 확대가 된다.

## 4. 반드시 통과해야 할 자동 검사 (도봉산역 데이터로 새로 작성)

군자역 테스트(`src/station/*.test.ts`, `src/guide/*.test.ts`)를 참고해서 역 데이터만 바꿔 같은 검사를 만든다.

| 검사 | 기준 |
|---|---|
| 데이터 무결성 | 계단 경사 1.1~2.2, 걷기 연결은 같은 층끼리만, 편의시설 번호가 API 목록과 일치 |
| 승강장 배치 | 계단·에스컬레이터·엘리베이터가 승강장 긴 변에서 1m 이상 안쪽, 서로 겹치지 않음 |
| 걷는 선 | 어떤 걷기 연결도 같은 층 계단 구멍·구조물을 가로지르지 않음 |
| 우회 | 같은 트인 구역 안 모든 두 지점: 경로 ≤ 직선 × 1.5 + 8m. 개찰구 → 다음 계단 입구: ≤ 직선 × 1.2 + 3m |
| 출구 ↔ 출구 | 개찰구 통과 0회, 아니면 '안내 안 함'(규칙 6-1)으로 처리되고 그 쌍이 예상한 것뿐임 |
| 전체 조합 | 출구·승강장·주요 지점 × 목적지 × 계단 없이 여부: 경로 존재(엘리베이터 없는 출구 제외), 개찰구 통과 횟수 정확(들어갈 때 1, 나갈 때 1, 환승 0, 개찰구에서 출발하면 첫 걸음 쪽 기준), 한 단계 한 층, 한 단계 걷기 150m 이하, 10단계 이하, 계단 없는 경로에 계단 없음, 승차권 구매 시 발매기가 개찰구보다 먼저 |
| 엘리베이터 위치 | API dtlPstn의 칸-문 번호에서 8m 이내 |
| 환승 문 | 환승정보 빠른 문이 해당 환승 계단에서 5m 이내 |
| 안내 보조 | 계단·에스컬레이터·개찰구 뒤 방향 안내, 단계 끝 주변 표식, 엘리베이터 버튼이 만들어짐 |

`npm --prefix app test`, `npx --prefix app tsc -b`, `npm --prefix app run build`가 모두 통과해야 한다. 군자역 테스트도 그대로 통과해야 한다.

## 5. 브라우저 확인 (캡처로 보여 줄 것)

1. 출구 → 승강장(승차권 구매 포함): 출구, 개찰구, 계단 입구, 계단, 타는 곳 단계마다 '내 앞'과 '위에서' 시점
2. 1호선 ↔ 7호선 환승 양방향
3. 계단 없이(엘리베이터만) 출구 → 승강장
4. 층 전체(층 버튼으로 한 층씩): 개찰구 안팎, 바닥 구멍, 울타리가 안내도와 같은 모양인지 나란히 비교
   - **이 비교는 데이터를 다 만든 뒤가 아니라 배치를 처음 잡은 직후에 한 번 먼저 한다.** 도봉산역에서는 1호선 승강장 위치가 그림과 다른 것을 마지막 비교에서야 발견해 테스트와 캡처를 다시 했다. (도봉산역에서 추가)
5. 안내 중 "길을 잃었어요"로 위치를 바꾼 뒤 같은 목적지로 다시 안내
   - 표지판 샘플 사진이 없는 역은 "사진 없이 위치 고르기"로 확인한다.

## 6. 결과 보고 형식

`docs/RESULTS-dobongsan.md`에 다음을 적고, 대화에는 요약만 쓴다.

- **대조표:** 항목마다 근거 자료, 판정(확인 / 추정 / 자료 없음), 오차
