### 규칙 후보 (PROMPT_new_station.md에 반영함: 1절 '먼저 확인할 것', 규칙 2·6-1·15·15-1, 4절 출구↔출구 검사, 5절 4·5번)
1. **개찰구 밖 구역이 둘 이상이면 서로 어떻게 이어지는지 먼저 정한다.** 역 안으로 이어지지 않으면 출구끼리 경로를 안내하지 않고 역 밖 길을 쓰게 한다. 검사: 출구 ↔ 출구 경로의 개찰구 통과 0회 또는 '안내 안 함'.
2. **단면도와 3D 그림, 환승정보가 어긋나면** 환승정보(칸-문)와 API dtlPstn처럼 숫자로 된 자료를 먼저 따른다. 단면도는 층 연결과 방향만 쓰고 가로 위치는 참고만 한다.
3. **긴 승강장(150m 이상)·긴 통로에는 가운데 확인 지점을 둔다.** 트인 공간 곧은 연결은 100m 이하로.
4. **타는 곳 노드는 승강장에 들어오는 모든 방향(계단·엘리베이터·환승 통로)에서 앞으로 걸어 닿는 자리**에 둔다. 들어오는 곳이 양 끝이면 그 사이에.
5. **운영사가 다른 노선은 칸 수·통행 방향(코레일 왼쪽 통행)을 따로 적는다.** 시간표·API가 없으면 화면에 "자료 없음"을 띄운다.
6. **지상·고가역은 지하역 가정(지상 → 지하 대합실 → 승강장)을 쓰지 않는다.** 출구가 여러 높이에 있을 수 있다(도봉산 1-1번).
7. 나란히 비교 캡처는 **데이터를 다 만든 뒤가 아니라 배치를 처음 잡은 직후**에 한다(5번 문제는 그때 바로 보였을 것).

## 5. 다루지 않은 것과 한계
- 좌표는 모두 근사(실측 아님). 1호선 쪽은 공공데이터가 없어 그림만 보고 채움.
- 1호선 에스컬레이터를 계단으로 표시(API에 없음). 실제로 에스컬레이터를 탈 수 있을 수 있다.
- 1호선 실시간 가동·시간표·환승 빠른 문(1→7): 자료 없음.
- 표지판 사진 인식 규칙(`locate/match.ts`)과 LLM 목록(`locate/catalog.ts`)은 군자역용 그대로다. 도봉산역에서는 출구 번호만 이 역의 출구로 바꾸고, 이 역에 없는 위치 후보는 버린다. 도봉산 표지판 사진·샘플은 없어 측정하지 않았다.
- 실시간 열차 도착(`server/arrivals.ts`)은 군자역 전용 그대로(키도 없음).
- '내 앞' 시점의 **첫 단계** 카메라가 멀리서 보이는 현상은 군자역에도 있는 기존 동작이라 고치지 않았다.
- 종착역 목록은 1호선 구로까지만(인천·신창·광명·서동탄 갈래 없음). 영문 표기는 공식 자료와 대조하지 않았다.

## 6. 두 역 이어서 안내 (군자 → 7호선 → 도봉산, 2026-11-28 추가)
군자역에서 도봉산역의 출구(또는 1호선 환승)까지 한 번에 고르면, 열차를 내린 문 앞에서 도봉산역 안내가 이어진다.

| 단계 | 화면 | 근거·방식 |
|---|---|---|
| 1. 계획 | 목적지 "도봉산"을 넣으면 "도봉산역에서 어디로 나가나요?"(1·1-1·2·3번 출구, 1호선 두 방면) | 도착역도 안내 데이터가 있을 때만 나온다 |
| 2. 군자역 안내 | 마지막 단계가 "타는 곳 7-4번 문에 도착", "도봉산 2번 출구에 가까운 문" | **빠른 하차 문**: 군자에서 그 문까지 + 도봉산에서 그 문부터 출구까지 걷는 거리의 합이 가장 짧은 문(칸-문 번호는 같은 열차라 두 역에서 같다) |
| 3. 열차 안 | 객차 안 그림(내리는 문 쪽 표시, 탄 칸·문), 지나는 역 띠, 도착 예정 시각, "'도봉산, Dobongsan' 방송이 나오면 내리세요" | 예상 시각 = 탄 시각 + 소요 시간. 소요 시간은 사이버스테이션 시간표의 **열차번호로 두 역 출발 시각을 맞춘 중앙값**(군자→도봉산 29분, 236편, 28~30분 / 도봉산→군자 28분). 실제 열차 위치가 아니라고 화면에 적음 |
| 4. 내림 | "도봉산에서 내렸어요" → 역이 도봉산으로 바뀌고(주소도 `?station=dobongsan`) 내린 문(7-4) 앞에서 출발 | 문 위치 모델로 그 문 앞(안전문 0.6m 안쪽)에 임시 지점을 넣고, 같은 승강장 안에서 구조물을 가로지르지 않는 지점들과 잇는다(100m 이하). 원래 데이터는 바꾸지 않음 |
| 5. 도봉산역 안내 | 첫 단계 "열차에서 내리면 오른쪽으로 도세요" → 계단 → 개찰구 → 2번 출구(4단계 102m) | 내린 직후 방향 = 선로 반대쪽(승강장 안쪽)을 본다고 보고 방향을 말함 |

- 열차 안 화면은 새로고침·연결 끊김 뒤에도 돌아온다(휴대폰 저장소). 출발역·도착역 안내 중 새로고침은 아직 이어지지 않는다.
- 반대 방향(도봉산 → 군자, 7호선 수락산 방면)도 같은 방식으로 동작한다(자동 검사).
- 내리는 문 방향(오른쪽/왼쪽)은 승강장 배치(상대식, 오른쪽 통행)로 계산한 값이다. 실제 열차 방송과 대조하지 않았다.

검사: `app/src/journey/journey.test.ts` 12개 — 노선 연결·소요 시간, 두 역 문 번호 일치, 내리는 문 방향, **두 방향 모두 모든 문(32) × 모든 출구·환승에서** 경로 존재·개찰구 횟수(출구 1, 환승 0)·10단계 이하·한 단계 150m 이하, 빠른 하차 문이 모든 문 중 최단, 1호선 환승 시 공식 빠른 환승 문(1-1·8-4) 15m 안, 계단 없이 고르면 두 구간 모두 계단 없음.
전체: `npm --prefix app test` **116개 통과**(군자 72 + 도봉산 32 + 여정 12), `tsc -b`·빌드 통과.

브라우저 확인: `docs/progress/journey-1`~`7` (계획 → 군자역 7-4번 문 → 열차에 탔어요 → 열차 안 → 새로고침 뒤 복구 → 도봉산 7-4번 문에서 출발, 내 앞·위에서).

만들면서 고친 것:
- 내린 문(8-4, 승강장 끝)에서 반대쪽 끝 계단까지 한 단계 154m — 임시 지점 연결도 100m로 제한하고, 엔진이 '이대로 가면 140m를 넘는' 걷기를 가까운 표식 이름(예: 엘리베이터 옆)으로 끊게 했다. 새 문제 → 규칙 후보: **임시로 넣는 지점도 역 데이터와 같은 연결 규칙(100m 제한·구조물 회피)을 따른다.**
